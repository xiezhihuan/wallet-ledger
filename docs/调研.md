# 截图账本 · 设计依据

核对日期为 2026-11-24。任务分支的基线为空提交，工作树已有未提交实现。以下结论取自上游文档、仓库和许可证，用于复核既有实现并决定交付方案。

| 项目、许可 | 看过的实践 | 对本产品的取舍 |
|---|---|---|
| [Actual Budget](https://github.com/actualbudget/actual)，[MIT](https://github.com/actualbudget/actual/blob/master/LICENSE.txt) | [报表](https://actualbudget.org/docs/reports/)区分现金流、净资产和支出分析。[导入](https://actualbudget.org/docs/transactions/importing/)先看外部 ID，再用日期与金额等字段匹配手工账 | 用户想知道钱花到哪里。保留商户、分类、预算和可回查明细，省去账户开户、期初余额与信封预算。近似匹配交给人判断 |
| [double-entry-generator](https://github.com/deb-sig/double-entry-generator)，[Apache-2.0](https://github.com/deb-sig/double-entry-generator/blob/master/LICENSE) | 其 provider 文档分别支持[微信 CSV/XLSX](https://deb-sig.github.io/double-entry-generator/providers/payment/wechat.html) 与[支付宝 CSV](https://deb-sig.github.io/double-entry-generator/providers/payment/alipay.html)。按交易字段与商户映射分类 | 借鉴表头定位、规则归类和收支区分。自己实现本地预览和逐行决策，保留截图与导入行的关联，无需生成复式分录 |
| [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR)，[Apache-2.0](https://github.com/PaddlePaddle/PaddleOCR/blob/main/LICENSE) | 检测框、识别文本、置信度适合还原标签和值的位置关系。离线模型能保留隐私 | 实际使用模型和 MIT 的 [ppu-paddle-ocr](https://www.npmjs.com/package/ppu-paddle-ocr) 运行库。OCR 只读文字，业务层另行判断实付、原价、余额、部分退款和多笔列表 |
| [Khorcha-Pati](https://github.com/masudur-rahman/khorcha-pati)，[Apache-2.0](https://github.com/masudur-rahman/khorcha-pati/blob/HEAD/LICENSE) | Telegram 对话记交易，网页管理预算与报表 | 借鉴聊天快速录入、网页纠错的分工。用户使用 QQ，截图需要离线识别及消息证据链，另建本地服务 |
| [腾讯 botpy](https://github.com/tencent-connect/botpy)，[MIT](https://github.com/tencent-connect/botpy/blob/master/LICENSE) | 腾讯提供的机器人 SDK。官方[鉴权](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/interface-framework/api-use.html)规定 AppID 和 Secret 换取短期令牌。[事件文档](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/interface-framework/event-emit.html)分别说明 Webhook 与 WebSocket，后者有 Identify、Heartbeat 和 Resume | 选择主动连出的 WebSocket，无需暴露本地数据库或开放公网回调。绑定后录入，持久化去重，提交后推进序号。具体机器人必须获平台相应权限 |
| [Actual Budget MCP](https://github.com/s-stefanov/actual-mcp)，[MIT](https://github.com/s-stefanov/actual-mcp/blob/main/LICENSE) | 提供账单筛选、分类、商户、月汇总，也有修改交易工具。分析数据附金额口径 | 采用独立 Bearer 令牌，写入再加管理员签发的短期授权码。MCP 与网页调用同一份统计逻辑，方便核对。[官方传输规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)规定 Streamable HTTP，客户端通过 initialize 协商，服务可不提供独立 GET 事件流 |

**官方账单格式的证据边界。** 已访问[微信客服](https://kf.qq.com/product/weixin.html)和[支付宝帮助中心](https://help.alipay.com/)。未获得两家针对个人用户导出文件的版本化列规范或官方测试账单。支持范围据公开 provider 资料和自制文件验证，包含微信 CSV/XLSX、支付宝 UTF-8/GB18030 CSV。实际使用先解压，再核对预览的来源、金额、状态与重复提示。商户对账 API 的格式不能代表个人账单。

**源码与许可。** 用户授权参照其天工反馈仓库 a5439e3。网关、OpenAPI、消息归一化、本地 OCR、附件队列、访问地址、备份、模拟平台和桌面打包沿用或改写该提交的同类模块。该仓库无对外开源许可证，此授权仅用于本次独立产品。财务模型、凭证解析、合并裁决、分类、导入、报表和界面在本仓库维护。社区财务项目仅作设计参考。运行依赖版本由 package-lock.json 锁定，许可证随各 npm 包保留；模型许可见 [models](../models/README.md)。
