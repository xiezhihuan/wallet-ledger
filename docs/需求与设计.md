# 需求与设计

一个人管理一个本地账本。输入可以是一段对话，输出是一笔可追溯的消费。允许绑定多个 QQ，它们共同管理同一本账。用户可以从报表金额一直查到交易、附件和修改记录。

## 录入如何变成账

| 对象 | 保存的信息及用途 |
|---|---|
| messages、attachments | 平台消息 ID、发送时间、发送人、文字与附件任务。消息去重键唯一。图片在本地按 SHA-256 命名，同一份文件可被多条消息引用 |
| evidence | 每段文字或每份附件的识别结果和归属账目。拆开、并入或补充时仍能回到原始证据 |
| bills | 交易类型、金额分、币种、商户、时间及时间来源、分类、支付方式、多个单号、备注、退款关联、疑似重复关系、状态和人工锁定字段 |
| categories、rules、budgets | 一级类与子类、商户和关键词规则、每月总预算与可选的一级分类预算 |
| events、imports | 操作者、变更原因和时间。文件导入保存行预览与选择结果 |
| qq_users、qq_refs、receipts_due、api_tokens | 绑定身份、引用映射、待发送回执、访问令牌哈希和撤销时间 |

QQ 网关使用心跳与恢复游标。绑定检查和消息去重先于记账。消息、素材和待回执在 SQLite 事务内提交，提交成功才推进网关序号。附件异步下载，限制体积、检查重定向并重试。下载失败有占位和重试入口。OCR 完成标记与归账一起提交，重启后继续处理未完成的任务。网关能否补回停机期间的消息，取决于平台是否仍允许恢复会话。

## 取舍

- 默认合并窗口为同一发送人的三分钟，以平台发送时间计算。网页可关闭或调整。无金额的说明跟随当前账，连续两条各带金额的完整文字通常分开。支付成功页加对应订单详情可合为一笔。明确冲突的实付金额、交易流水号、不同商户优先拆开。通用平台商户名可由订单里的实际商家补全。
- 同一事件重投只处理一次。用户主动重发同一图片，即使还在同一窗口，也会产生可裁决的重复候选。同单号或金额、商户和时间足够接近会提示，候选不增加消费。用户可以并回去保留素材，也可以确认另记。
- 引用或指定编号表示主动补到旧账。人工改过的字段会锁定，后到的识别结果不能覆盖它。单图账单列表单独暂存，先列出再选择行。全部入账默认跳过疑似重复或未成功的行。
- OCR 检测框保留文字坐标和置信度，长图重叠切片后按中心线归属。解析优先读取实付及交易动作，排除折扣、余额、积分与费用小计。未支付、已取消、多币种或多个实付冲突、全图低置信度等情况交给用户核对。缺支付方式或商户可先记，以回执提示。缺时间使用明确标记的发送时间。
- 语音采用 QQ 事件中的转写文字，记录识别来源。没有转写时保留附件供补充。软件本身无需联网调用语音或图像识别服务。
- 一个确认收入或支出只属于一个分类。归类优先级为用户商户规则、包含规则、订单场景、关键词。网页改分类可选择是否记住，撤销规则影响今后的匹配。
- 文件导入按表头识别来源。预览逐行说明新账、同单号、疑似、非成交和文件内重复。提交时再次检查，以处理预览之后新出现的交易。个人对账文件各版本的验证边界见[调研](调研.md)。

## 钱按什么口径加总

业务时间为 Asia/Shanghai，周一至周日，自选区间含首尾两天。金额按整数分存储和加减。默认 CNY，外币保留币种和原金额，按币种单列。

| 项目 | 口径 |
|---|---|
| 净消费 | 已入账人民币支出减退款。待确认、疑似重复、多笔列表、收入、转账、还款不进入默认合计。显式包含待确认时，只把有金额的待确认纳入估算 |
| 退款 | 有原支出关联时，默认冲减原消费日期，并沿用原分类和商户。没有关联时按退款到账日期。可以改为全部按到账日期冲减 |
| 跨期举例 | 12 月买鞋 100 元，次年 1 月退 40 元。关联后，默认 12 月净消费 60 元、1 月 0 元。切换到账口径后为 100 元和 −40 元。两个月累计都是 60 元 |
| 笔数、日均 | 笔数统计支出交易，退款另列。日均用净消费除以已过天数，结束的期间采用全部天数。进行中的月份与上期、去年同期比较时另给同进度数值 |
| 分类占比、排序和预算 | 分类净消费除以本期净消费，显示值可因舍入略有差异。趋势、排行榜和明细使用相同日期与过滤条件。预算按月复用，达到 80% 提示，超过预算显示超支额 |

总览、统计、QQ 查询、MCP 都使用 Stats 和 Store 的计入条件。退款有效日期、有效商户和分类在同一账单视图中处理。原始交易时间仍可在详情核对。

## 运行与隔离

桌面界面通过 Electron 载入本地网页，账本服务运行在独立进程中。首次启动选择空闲端口，默认仅回环监听。程序标识为 `com.walletledger.personal`，密钥使用独立的 WalletLedger safe storage。网页以密码登录，修改请求检查来源标记。生产模式禁用演示聊天接口。

MCP 使用独立 Bearer 令牌，只启用七个查询工具。每个请求重新验证撤销状态。工具说明要求把截图、文字、商户名作为外部资料。搜索每页最多 50 条，详情文字每段 8,000 字符，图片长边最多 1,280 像素，工具响应限制 2 MiB。截图中的长号码通过 OCR 坐标遮盖，无法识别的图不经 MCP 返回。只有用户接入 AI 后，返回的查询结果才交给对应客户端。

SQLite 使用 WAL、FULL 同步和外键。自动备份通过数据库快照及按内容保存的共享附件副本实现，恢复时校验数据库完整性与文件哈希，保留当下的安全权限。应用不提供远端同步。
